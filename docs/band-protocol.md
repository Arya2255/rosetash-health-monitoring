# پروتکل BLE مچ‌بند Porodo PDMB1062

> وضعیت: ✅ کشف شد و با تست زنده تأیید شد — ۲۰۲۶-۱۰-۱۰
> منبع: مهندسی معکوس اپ Porodo Fit نسخهٔ ۱٫۲٫۵ — مسیر داخلی Fundo/KCT
> مصرف‌کننده: فاز ۲ — گیتوی ESP32 و بک‌اند دقیقاً همین توالی را پیاده می‌کنند.

## سرویس و کاراکتریستیک‌ها

| مورد | UUID | خاصیت |
|---|---|---|
| سرویس اصلی | `4cdabaa0-2cea-c0c1-b38d-a0481ae60a97` | — |
| کانال فرمان | `4cdabaa1-2cea-c0c1-b38d-a0481ae60a97` | Write Without Response |
| کانال رویداد | `4cdabaa2-2cea-c0c1-b38d-a0481ae60a97` | Notify |
| باتری استاندارد | سرویس `180F` → `2A19` | Read + Notify |
| آپدیت فریمور | Nordic DFU — `FE59` | OTA |

- احراز هویت و جفت‌شدن لازم **نیست** — اتصال مستقیم کافی است.
- مچ‌بند **نمایشگر ندارد** و نتیجهٔ اندازه‌گیری فقط از طریق اپ دیده می‌شود.
- مچ‌بند فقط زمانی «آگهی» پخش می‌کند که به میزبان دیگری وصل نباشد — برای تست، بلوتوث گوشی خاموش باشد.

## فرمت فریم

```
OUTER:  BA | 21 (اپ) یا 31 (مچ‌بند) | طول بدنه (۲ بایت BE) | CRC16 (۲ بایت) | شماره (۲ بایت) | INNER
INNER:  cmd1 | 00 | cmd2 | طول داده (۲ بایت BE) | داده...
```

- CRC16 روی بدنهٔ داخلی محاسبه می‌شود — الگوریتم SDK با مقدار اولیه `0xFFFF`؛ پیاده‌سازی مرجع در `tools/band/fundo_send.py` تابع `crc16`.
- صحت CRC روی همهٔ فریم‌های واقعی مچ‌بند تأیید شده است.

نمونهٔ فریم واقعی:

```
BA 31 00 06 92 81 00 00 02 00 71 00 01 01                              ← پاسخ «شروع شد»
BA 21 00 0D 5A 6C 03 00 0A 00 AB 00 08 59 00 1A 0A 0A 14 09 31         ← ضربان لحظه‌ای
```

## جریان اندازه‌گیری ضربان قلب — تأییدشده با تست زنده

| # | جهت | فریم | معنی |
|---|---|---|---|
| ۱ | لپ‌تاپ → مچ‌بند | `(02,70)` داده `[01,01]` | شروع اندازه‌گیری — نوع ۱ = ضربان |
| ۲ | مچ‌بند → لپ‌تاپ | `(02,71)` داده `[01]` | قبول شد — مقدار `[00]` یعنی خطای پوشیده‌نبودن |
| ۳ | مچ‌بند → لپ‌تاپ | `(0A,AB)` هر ۲-۳ ثانیه | **بایت اول = ضربان قلب** — فریم ۸ بایتی |
| ۴ | مچ‌بند → لپ‌تاپ | `(02,72)` داده `[01]` | پایان — ۱=ضربان، ۲=اکسیژن، ۶=HRV، ۷=ترکیب بدن، ۸=دما |

ساختار دادهٔ ضربان:

```
[BPM, 00, 1A, 0A, 0A, 14, شمارنده, تیک]
```

هر دور اندازه‌گیری حدود ۲۰-۲۵ ثانیه است و خودش تمام می‌شود؛ دور بعدی بلافاصله قابل شروع است.

## دستورهای دیگر

| فریم | معنی | وضعیت |
|---|---|---|
| `(04,41)` | باتری `[درصد, حالت]` — خود مچ‌بند دوره‌ای می‌فرستد | تأییدشده |
| `(A6,05)` ← `(A6,06,[01])` | روشن کردن گزارش‌گیری لحظه‌ای | تأییدشده |
| `(A7,1F)` | دستور پس از اتصال — مچ‌بند همان را بازمی‌گرداند | تأییدشده |
| `(A7,37)` | زمان‌بندی ضربان خودکار `[فعال, ساعت شروع, دقیقه, ساعت پایان, دقیقه, فاصله]` | از SDK |
| `(02,20)` | تنظیم ساعت `[سال-2000, ماه, روز, ساعت, دقیقه, ثانیه, پرچم, منطقه‌زمانی]` | از SDK |
| `(0A,73)` / `(0A,74)` | وضعیت و پیشرفت حین اندازه‌گیری | از SDK |

خانوادهٔ کامل دادهٔ لحظه‌ای در پروتکل وجود دارد — ضربان، اکسیژن، فشار، استرس، دما، قند، قدم. الگوی فریم یکسان است؛ برای هر سنسور فقط شمارهٔ نوع در فرمان عوض می‌شود.

## نتایج تست زنده — ۲۰۲۶-۱۰-۱۰

| دور | نمونه‌ها (BPM) | میانگین | پایان |
|---|---|---|---|
| ۱ | 95 → 94 → 93 → 92 | 93.5 | تمیز |
| ۲ | 90 → 91 → 92 → 93 | 91.5 | تمیز |
| ۳ | 62 → … → 69 | 65.5 | تمیز |

سه دور پشت‌سرهم — هر سه: تاییدیهٔ شروع، نمونه‌های پیوسته، پایان خودکار. یک تلاش اتصال ناموفق هم خودکار جبران شد.

## پیامد برای فاز ۲ — گیتوی ESP32

- حضور با فیلتر UUID کوتاه `0xBAA0` روی بستهٔ پخش آگهی کار می‌کند — اسکن فعال فقط برای خواندن نام لازم است.
- ضربان فقط با **اتصال + فرمان** می‌آید — گیتوی باید نوبتی وصل شود، فرمان `(02,70)` بدهد و فریم‌های `(0A,AB)` را جمع کند.
- مچ‌بند هم‌زمان فقط یک اتصال می‌پذیرد — برای چند کارکن، اتصال‌ها باید نوبتی باشند.
- مچ‌بند باید روی دست بسته باشد؛ وگرنه پاسخ خطای پوشیده‌نبودن می‌آید.

## گیتوی ESP32 — نتایج و پیت‌فال‌ها (۲۰۲۶-۱۰-۱۱)

سه کشف کلیدی هنگام پیاده‌سازی روی گیتوی:

| پیت‌فال | نشانه | راه‌حل |
|---|---|---|
| UUID آگهی | گیتوی هرگز مچ‌بند را «نمی‌دید» | بستهٔ پخش آگهی UUID کوتاه `0xBAA0` را تبلیغ می‌کند نه UUID سفارشی؛ نام فقط در پاسخ اسکن می‌آید → اسکن فعال + پذیرش `0xBAA0` |
| توقف اسکن | شمارندهٔ دریافت بعد از اولین تلاش اتصال منجمد می‌شد | NimBLE هنگام اتصال اسکن را stop می‌کند و برنمی‌گرداند → واچ‌داگ ری‌استارت در poll() |
| CCCD بدون پاسخ | اتصال و فرمان «موفق» ولی هیچ نوتیفایی نمی‌آمد | مچ‌بند نوشتن CCCD بدون پاسخ را نادیده می‌گیرد → `subscribe(true, lambda, true)` — با پاسخ |

**تست کامل از راه دور (نسخهٔ 0.1.3):** گیتوی وصل شد، فرمان ضربان فرستاد و ۵ نمونه دریافت و در MQTT منتشر کرد:

```
bpm: [79, 78, 77, 76, 74]  avg: 76.8  wearing: true  ended: true
```

مچ‌بند روی دست کاربر با rssi ≈ -85 — تضعیف بدن سیگنال را کم می‌کند ولی اتصال پایدار بود و چرخه هر دقیقه تکرار می‌شود.

## باتری، اطلاعات دستگاه، اکسیژن و HRV — تأییدشدهٔ زنده (۲۰۲۶-۱۰-۱۱)

با فِرمویر گیت‌وی ۰٫۱٫۴ این چهار مورد روی مچ‌بند واقعی آزمایش و در MQTT منتشر شدند:

| قابلیت | مسیر | مقدار دیده‌شده |
|---|---|---|
| باتری | سرویس استاندارد `180F` → خواندن `2A19` + پوش دوره‌ای `(04,41)` | ۹۰٪ |
| اطلاعات دستگاه | سرویس استاندارد `180A`: `2A29` سازنده، `2A28` نسخهٔ نرم‌افزار، `2A27` نسخهٔ سخت‌افزار | OnMicro — نرم‌افزار ۲٫۰٫۲٫۳ — سخت‌افزار ۱٫۰٫۰٫۰ |
| اکسیژن خون | `(02,70)` داده `[01,02]` | پذیرش `(02,71,[01])` و پایان `(02,72,[02])` — نتیجه در فریم `(0A,B2)` با ۷ بایت داده |
| HRV | `(02,70)` داده `[01,06]` | پذیرش و پایان `(02,72,[06])` |

نکته‌های کلیدی:

- فرمان شروع برای همهٔ سنسورها یکسان است: `(02,70)` با دو بایت `[01, نوع]`؛ فقط شمارهٔ نوع عوض می‌شود (۱=ضربان، ۲=اکسیژن، ۶=HRV).
- فریم پایان `(02,72)` نوع تمام‌شده را در بایت داده می‌آورد — همان‌جا تأیید می‌شود که نوع درست اجرا شده است.
- فریم نتیجهٔ اکسیژن `(0A,B2)` **بلافاصله بعد از** فریم پایان می‌رسد؛ اگر مرحلهٔ بعدی بی‌درنگ شروع شود از دست می‌رود. گیت‌وی ۱٫۵ ثانیه پنجرهٔ ته‌نشینی نگه می‌دارد.
- بایت اول فریم `(0A,B2)` وقتی مچ‌بند روی دست **نباشد** صفر است (نمونهٔ واقعی: `00 1A 0A 0B 02 2C 2D`). پارسر SDK اپ همین بایت را درصد می‌خواند؛ پس قرائت معتبر باید در بازهٔ ۷۰ تا ۱۰۰ باشد.
- باتری و اطلاعات دستگاه GATT استانداردند و در **هر اتصال** خوانده می‌شوند؛ مراحل اکسیژن و HRV سنگین‌اند و گیت‌وی آن‌ها را هر پنج پنجرهٔ سلامت یک‌بار اجرا می‌کند (محافظت از باتری مچ‌بند).

## ابزارها — `tools/band/`

```
fundo_send.py       فرستندهٔ عمومی فریم + اسکن خودکار و تلاش مجدد اتصال
hr_live.py          خوانندهٔ پیوستهٔ ضربان — چند دور اندازه‌گیری + ثبت CSV
features_probe.py   کاوش قابلیت‌ها — باتری، اطلاعات دستگاه، اکسیژن، HRV، گزارش لحظه‌ای
```

نصب و اجرا:

```
python3 -m venv .venv
.venv/bin/pip install bleak
.venv/bin/python tools/band/hr_live.py --address <MAC> --rounds 3 --interval 30 --csv hr_log.csv
```
