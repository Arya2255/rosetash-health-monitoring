## 🧭 قبل از شروع — ESP32 در یک نگاه

ESP32 یک برد کوچک کامپیوتری است (به اندازهٔ کف دست) با وای‌فای و بلوتوث داخلی. کاری که از آن می‌خواهیم: در سالن کارخانه بنشیند، مچ‌بندهای کارکنان را با بلوتوث ببیند، ضربانشان را بگیرد و داده را با وای‌فای به سیستم HSE بفرستد. هیچ دانش قبلی از ESP32 لازم نیست — هر اصطلاحی که لازم شود، همان‌جا توضیح داده شده.

> 🔍 وضعیت تأیید — روی این لپ‌تاپ و برد واقعی (۲۰۲۶-۱۰-۱۰) آزمایش شد: نصب arduino-cli ✅ · نصب هستهٔ ESP32 ✅ · نصب کتابخانه‌ها ✅ · کامپایل فریمور ✅ · فلش روی برد ✅ · بوت و اسکن BLE با لاگ تمیز ✅. هنوز مانده: پروویژن وای‌فای و config.json، تست حضور با مچ‌بند، تست MQTT.

## 🧰 تجهیزات لازم

- برد توسعهٔ ESP32 با پورت Type-C — بردِ رسیده از خانوادهٔ ZY-ESP32 است؛ پین‌آوت و چیپش در ردهٔ ESP-WROOM-32 است (۳۰ یا ۳۸ پایه — برای این فریمور تفاوتی ندارد) و با همین راهنما کار می‌کند
- کابل USB Type-C **دیتادار** — کابل‌های «فقط شارژ» هیچ‌وقت پورت سریال نمی‌سازند؛ شایع‌ترین اشتباه همین است
- آداپتور ۵ ولت / ۱ آمپر + کابل برای نصب دائم در کارخانه
- یک مچ‌بند PDMB1062 برای تست (باید روی دست بسته باشد)
- دسترسی به وای‌فای کارخانه — همان شبکه‌ای که سیستم HSE روی آن است (هر گیتوی با وای‌فای خودش مستقیم به سیستم HSE وصل می‌شود)

## 🐧 گام ۱ — آماده‌سازی لینوکس

### ۱-۱ دیدن پورت برد

برد را وصل کن و بزن:

```
ls /dev/ttyUSB*
```

انتظار: `/dev/ttyUSB0`. درایور هر دو مبدل رایج (CP2102 و CH340) داخل کرنل لینوکس است و پلاگ‌اندپلی کار می‌کند. برای اطمینان:

```
dmesg | tail -5
```

باید چیزی شبیه این باشد:

```
cp210x 1-1:1.0: cp210x converter detected
usb 1-1: cp210x converter now attached to ttyUSB0
```

### ۱-۲ عضویت در گروه dialout

بدون این عضویت، باز کردن پورت رد می‌شود:

```
sudo usermod -aG dialout $USER
```

بعد یک بار خروج و ورود. بررسی:

```
groups | grep dialout
```

> ✅ وضعیت لپ‌تاپ مرجع — ۲۰۲۶-۱۰-۱۰: کاربر عضو dialout شد و اولین فلش انجام شد. نکته: در ترمینال‌هایی که قبل از عضویت باز شده‌اند، بدون خروج/ورود هم با `sg dialout -c 'دستور'` دسترسی به پورت هست.

### ۱-۳ اگر پورت نیامد — تلهٔ brltty

روی مینت و اوبونتو، سرویس brltty گاهی پورت USB-سریال (CP2102 یا CH340) را قبل از تو می‌گیرد و پورت ظاهر نمی‌شود:

```
sudo systemctl stop brltty-udev.service
sudo systemctl mask brltty-udev.service
```

> وضعیت لپ‌تاپ مرجع — ۲۰۲۶-۱۰-۱۰: سرویس brltty-udev غیرفعال بود و مزاحم نشد — برد وصل شد و پورت بدون مشکل ساخته شد. این تله برای آینده اینجا می‌ماند.

## ⚙️ گام ۳ — تنظیم گیتوی

گیتوی تنظیماتش را از فایل `config.json` روی حافظهٔ داخلی (LittleFS) می‌خواند. بدون فایل، با مقدارهای پیش‌فرض بالا می‌آید — برای تست سریع روی میز کافی است، ولی برای وای‌فای و MQTT واقعی باید فایل را بسازیم.

نمونهٔ `config.json` — نام کلیدها دقیقاً همین‌ها باشد:

```json
{
  "gw_id": "gw-hall-1",
  "zone": "سالن اصلی",
  "wifi_ssid": "RoztashWiFi",
  "wifi_pass": "رمز-وای-فای",
  "mqtt_host": "192.168.1.10",
  "mqtt_port": 1883,
  "health_interval_s": 600,
  "scan_interval_ms": 160,
  "scan_window_ms": 80,
  "measure_timeout_s": 45
}
```

- `gw_id` نام همین گیتوی است و در موضوع پیام‌های MQTT می‌آید — با نام منطقه در برنامه یکی باشد
- `mqtt_host` آدرس سیستم HSE است — همان ماشینی که بروکر MQTT (Mosquitto) روی آن اجرا می‌شود؛ گیتوی با وای‌فای خودش به همین آدرس وصل می‌شود
- برای تست سریع، `health_interval_s` را روی `60` بگذار تا پنجرهٔ سلامت هر دقیقه باز شود؛ مقدار کارخانه `600` بماند
- فایل را در `firmware/gateway/data/config.json` بگذار — و **در گیت کامیت نکن** (رمز وای‌فای داخلش است؛ در gitignore قرار می‌گیرد)

فلش فایل تنظیمات روی برد — بعد از نصب هسته و با برد متصل:

```
cd ~/Projects/rosetash-health-monitoring

~/.arduino15/packages/esp32/tools/mklittlefs/*/mklittlefs -c firmware/gateway/data -s 0x20000 -p 256 firmware/gateway/littlefs.bin

~/.arduino15/packages/esp32/tools/esptool_py/*/esptool --chip esp32 --port /dev/ttyUSB0 write_flash 0x3D0000 firmware/gateway/littlefs.bin
```

> ✅ روی این لپ‌تاپ بررسی و تأیید شد — ساخت ایمیج LittleFS با mklittlefs تست شد. آفست و اندازه از پارتیشن `min_spiffs` هستهٔ ۳٫۳٫۱۲: `0x3D0000` و `0x20000`. مسیر ابزارهای همراه هسته: `tools/mklittlefs/*/mklittlefs` و `tools/esptool_py/*/esptool`. خودِ فلش به برد متصل نیاز دارد.

## 🔨 گام ۴ — کامپایل و فلش فریمور

```
cd ~/Projects/rosetash-health-monitoring

arduino-cli compile --fqbn "esp32:esp32:esp32:PartitionScheme=min_spiffs" firmware/gateway

arduino-cli upload --fqbn "esp32:esp32:esp32:PartitionScheme=min_spiffs" -p /dev/ttyUSB0 firmware/gateway
```

> ✅ روش فلش تأییدشده روی برد ZY-ESP32 (۲۰۲۶-۱۰-۱۰): باینری ادغام‌شدهٔ بیلد با esptool مستقیم فلش شد — پایدارتر و ساده‌تر:
>
> ```
> ~/.arduino15/packages/esp32/tools/esptool_py/*/esptool --chip esp32 --port /dev/ttyUSB0 --baud 460800 write_flash 0x0 firmware/gateway/build/esp32.esp32.esp32/gateway.ino.merged.bin
> ```
>
> نکته: در باود 921600 استابِ فلشر این برد خطا می‌دهد؛ با 460800 بدون خطا فلش می‌شود (~۳۰ ثانیه) و خودکار هش را verify می‌کند. فایل merged.bin همه‌چیز را یکجا دارد — بوت‌لودر + جدول پارتیشن + برنامه — و از آفست 0x0 نوشته می‌شود.

> ✅ کامپایل روی این لپ‌تاپ با موفقیت انجام شد (۲۰۲۶-۱۰-۱۰) — باینری ۱٫۲۳ مگابایت از ۱٫۹۶ مگابایت پارتیشن (۶۲٪) و رم ۵۹ کیلوبایت از ۳۲۰ کیلوبایت (۱۸٪). طرح `min_spiffs` عمدی است: با طرح پیش‌فرض مصرف به ۹۴٪ می‌رسید و افزودن فیچرهای بعدی (مثل سنسور دما) سرریز می‌کرد.

- اگر آپلود اول گیر کرد: دکمهٔ BOOT روی برد را نگه دار، یک‌بار EN را بزن و رها کن تا برد به مود بوت برود؛ بعد دوباره آپلود کن
- دیدن پیام‌های زندهٔ برد:

```
arduino-cli monitor -p /dev/ttyUSB0 -c baudrate=115200
```

> ⚠️ پیت‌فال لپ‌تاپ مرجع: اگر بلافاصله بعد از کار esptool پورت را با stty/تغییر باود باز کنی، ممکن است سیل زبالهٔ چندمگابایتی ببینی (آرتیفکت درایور USB این لپ‌تاپ — نه برد). راه تمیز: `uv run python tools/capture_gateway.py` — تک‌پروسه، پورت را یک‌بار باز می‌کند، ریست نرم با RTS می‌دهد و یکپارچه می‌خواند.

## 🧪 گام ۵ — تست روی میز

خروجی موردانتظار سریال بعد از روشن شدن:

```
rst:0x1 (POWERON_RESET),boot:0x13 (SPI_FAST_FLASH_BOOT)
[gw] boot — fw 0.1.0-skeleton
[cfg] /config.json not found — using defaults
[gw] wifi: not connected (continuing)
[ble] scanning (int=160 win=80 ms)
[gw] ready
```

> ✅ همین خروجی درست، روی برد واقعی گرفته شد (۲۰۲۶-۱۰-۱۰). وقتی config.json روی LittleFS فلش شود، جای خط `using defaults` پیام `[cfg] loaded: ...` و جای `not connected` آدرس IP می‌آید.
```

### ۵-۱ تست MQTT

از لپ‌تاپ یا هر ماشینی که به بروکر دسترسی دارد:

```
mosquitto_sub -h 192.168.1.10 -t 'roztash/#' -v
```

انتظار:

- هر ۶۰ ثانیه پیام `status` — گیتوی آنلاین با IP و RSSI وای‌فای
- هر ۱۰ ثانیه پیام `presence` — بستهٔ مچ‌بندهای دیده‌شده
- اگر دستور نصب نیست: `sudo apt install mosquitto-clients`

### ۵-۲ تست حضور

مچ‌بند روی دست، نزدیک برد. بلوتوث گوشی را خاموش کن — مچ‌بند تا وقتی به جایی وصل باشد آگهی پخش نمی‌کند. MAC مچ‌بند باید در بستهٔ `presence` بیاید.

### ۵-۳ تست ضربان قلب

صبر کن پنجرهٔ سلامت باز شود (با `health_interval_s: 60` هر دقیقه)، یا برد را ریست کن. انتظار در سریال:

```
[gw] health window 2 open (1 bands seen)
[ble] health job started: F3:B6:D6:B7:47:D7
[mqtt] health -> {"gw":...,"bpm":[...],"avg":...}
```

- اگر `wearing_error` دیدی: مچ‌بند محکم روی دست بسته نیست
- قطع اتصال بعد از هر اندازه‌گیری عمدی است — تا آگهی پخش دوباره جریان بگیرد و اسکن حضور کور نشود
