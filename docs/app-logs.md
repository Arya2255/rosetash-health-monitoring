# لاگ خودِ برنامه و خروجی پشتیبانی

پس از انتشار برنامه روی سیستم HSE، برای عیب‌یابی باید بدانیم «داخل برنامه چه
خبر بوده». این قابلیت لاگ فایل‌محور برنامه + صفحهٔ مشاهده + بستهٔ zip پشتیبانی
را می‌سازد. کد لاگر: `src/applog.py` — نمای صفحه: `src/views/logs.py`.

## فایل لاگ کجاست؟

هر اجرای برنامه یک فایل سشن در پوشهٔ `logs` کنار برنامه می‌سازد:

    logs/app-YYYYMMDD-HHMMSS.log        نمونه: logs/app-20261011-170512.log

- متغیر محیطی `ROZTASH_LOG_DIR` (املای `ROSETASH_LOG_DIR` هم قبول است) مسیر را
  عوض می‌کند — مثلاً روی USB یا پوشهٔ داده‌ی مستقل.
- `ROZTASH_LOG=0` لاگ فایلی را کامل خاموش می‌کند (همان قاعدهٔ `ROZTASH_LIVE=0`).

قالب هر سطر:

    2026-10-11 17:05:12 | WARNING | live | پل درخواست /api/employees را رد کرد — duplicate

مهر زمانی کامل (ثانیه) + سطح + ماژول + پیام. سطرهای `traceback` بدون مهر
زمانی می‌آیند و به سطر خطای بالای خود تعلق دارند.

## چرخش و نگهداری

- هر فایل سشن بیش از `MAX_BYTES` (۲۵۶ کیلوبایت) که شد، به `.log.1` می‌چرخد؛
  حداکثر `BACKUPS` (۲) نسخهٔ پشتیبان در هر سشن.
- فقط `MAX_SESSIONS` (۱۲) سشن آخر نگه داشته می‌شود؛ قدیمی‌ترها در راه‌اندازی
  سشن تازه پاک می‌شوند.

## چه رخدادهایی ثبت می‌شود؟

| کجا | چه چیزی |
|-----|---------|
| `src/main.py` | شروع/پایان اپ، بسته‌شدن پنجره/قطع نشست، جابه‌جایی صفحه‌ها، خطای ساخت صفحه (با `traceback`)، خطای رسیدگی‌نشدهٔ رابط، قلاب سراسری خطاهای نادیده‌گرفته‌شده (رشتهٔ اصلی و رشته‌های فرعی) |
| `src/live.py` | خطای اتصال به پل (یک‌بار در لحظهٔ گذار، همراه نشانی و نوع خطا)، بازگشت از دادهٔ نمایشی به زنده، فرمان‌ها (لرزش) و قبول/رد درخواست‌های ثبت و حذف |

هیچ خطایی بی‌صدا نمی‌ماند: قلاب سراسری (`install_hooks`) خطاهای uncaught را با
رد کامل در فایل می‌نویسد.

## صفحهٔ «لاگ برنامه»

تنظیمات ← کارت «لاگ برنامه» ← «مشاهدهٔ لاگ» (کلید نما: `logs`).

- آخرین ۴۰۰ سطر؛ تازه‌ترین خط بالا؛ به‌روزرسانی خودکار هر ۲ ثانیه
- فیلتر سطح: همه / اطلاعات / هشدار (هشدار + خطا) / خطا
- جستجوی متنی در سطرها
- «خروجی zip» — بستهٔ پشتیبانی

## بستهٔ پشتیبانی (zip)

دکمهٔ «خروجی zip» در صفحهٔ لاگ یا کارت تنظیمات، فایل زیر را می‌سازد:

    logs/roztash-logs-YYYYMMDD-HHMMSS.zip

محتوای بسته:

- `session-info.txt` — نسخهٔ برنامه، زمان خروجی، میزبان، سیستم‌عامل، نسخهٔ
  پایتون، پوشهٔ لاگ و فهرست فایل‌ها (خوانا حتی با Notepad)
- فایل‌های `app-*.log` پنج سشن اخیر (`EXPORT_SESSIONS`)

این zip بیرون از برنامه و روی هر سیستمی باز و خوانده می‌شود — همان چیزی که در
پشتیبانی فرستاده می‌شود.

## حریم خصوصی

- هیچ مقدار خام سلامت (ضربان، اکسیژن، HRV و…) در لاگ نوشته نمی‌شود؛ فقط
  رخدادهای فنی.
- شناسهٔ مچ‌بند در صورت نیاز با `applog.mask_mac` کوتاه می‌شود:
  `88:57:21:B8:AC:29` → `88:57:**:**:AC:29`.

## تست‌ها

    uv run python tests/test_applog.py     # لاگر، فیلترها، zip، قلاب، گذار پل
    uv run python tests/test_logs_ui.py    # صفحهٔ لاگ: رندر، فیلتر، جستجو، خروجی
    uv run python scripts/smoke_ui.py      # دود: ساخت همهٔ صفحه‌ها (و صفحهٔ لاگ)

## عیب‌یابی

- هیچ فایلی در `logs` نیست؟ `ROZTASH_LOG=0` را چک کن و دسترسی نوشتن پوشه.
- خطای اتصال پل در صفحهٔ لاگ نیست؟ شاید پل همان لحظه بالا بوده؛ لاگر گذارِ
  وضعیت را ثبت می‌کند (قطعی‌های کوتاه با کش چهارثانیه‌ای ممکن است فقط در
  حفظِ خط اول دیده شوند).
- خروجی zip خالی است؟ یعنی هنوز هیچ سشن لاگی ساخته نشده (برنامه درست اجرا نشده
  یا لاگ خاموش بوده).

لاگ خودِ پل (`backend/bridge.py`) جداست و در کنسول همان پردازه دیده می‌شود؛ این
قابلیت لاگ **برنامهٔ رابط کاربری** است.
