# آماده‌سازی گیتوی ESP32-S3 از داخل برنامه

صفحهٔ «آماده‌سازی گیتوی» شناسه/منطقه را در فایل تنظیمات می‌گذارد و فریمور را از راه USB روی برد می‌نویسد. برد گیتوی هدف ESP32-S3 N16R8 با W5500، فلش ۱۶ مگابایت و PSRAM هشت مگابایت است.

## شبکهٔ گیتوی

- W5500 با SPI به ESP32-S3 وصل است: SCK=GPIO12، MISO=GPIO13، MOSI=GPIO11، CS=GPIO10، RST=GPIO9؛ این اتصال با خواندن `VERSIONR=0x04` آزمایش شد.
- هنگام نصب، پورت RJ45 ماژول W5500 را به سوئیچ اترنت همان بخش وصل کنید.
- ESP32 از DHCP آدرس می‌گیرد؛ SSID و رمز Wi-Fi جزو تنظیمات گیتوی نیستند.
- گیتوی پس از گرفتن IP، بروکر MQTT کامپیوتر HSE را با UDP کشف می‌کند. `192.168.50.1:1884` فقط مقدار جایگزین است.
- هر گیتوی باید شناسهٔ یکتا مثل `gw-filter-1` و منطقهٔ مشخص مثل «فیلتر» داشته باشد.

## بستهٔ فلش همراه برنامه

مسیر: `distribution/gateway-provisioner/`

```text
firmware/             bootloader, partitions, boot_app0, app, LittleFS image
tools/windows-amd64/  esptool.exe و mklittlefs.exe برای فلش داخل برنامه
tools/linux-x86_64/   mklittlefs
manifest.json         چیپ، اندازهٔ فلش، نسخه، آدرس‌ها و SHA-256 فایل‌ها
```

نسخهٔ فعلی بسته `0.4.0-ethernet` است. بسته برای ESP32-S3/16MB ساخته شده؛ موتور برنامه نسخه‌ها و مشخصات چیپ را کنترل می‌کند و بستهٔ قدیمی ESP32/4MB را رد می‌کند.

چیدمان فایل‌ها برای برد جدید:

| فایل | آدرس فلش |
|---|---|
| bootloader.bin | `0x0` |
| partitions.bin | `0x8000` |
| boot_app0.bin | `0xe000` |
| app.bin | `0x10000` |
| littlefs.bin | `0x3D0000` |

آدرس آغازگر برد قدیمی نباید استفاده شود. برنامه تعداد فایل‌ها، آدرس‌ها، هندسهٔ پارتیشن، اندازه و هش فایل‌ها را پیش از فلش بررسی می‌کند.

برای ساخت دوباره پس از تغییر سورس:

```bash
uv run python tools/build_provisioner_bundle.py
```

## روند استفاده در برنامه

۱. ESP32 را با کابل USB دیتادار وصل کنید، فهرست پورت‌ها را اسکن و پورت برد را انتخاب کنید.
۲. «خواندن و تأیید مشخصات برد» را بزنید. برنامه MAC، مدل چیپ و اندازهٔ فلش را می‌خواند؛ فقط ESP32-S3 با فلش ۱۶ مگابایت پذیرفته می‌شود.
۳. شناسهٔ یکتا، نام نمایشی و منطقه را وارد کنید. آدرس جایگزین بروکر و پورت MQTT معمولاً `192.168.50.1` و `1884` باشد؛ کشف UDP در حالت عادی نشانی HSE را پیدا می‌کند.
۴. «شروع فلش کامل» فریمور، پارتیشن‌ها و `config.json` همان گیتوی را می‌نویسد. شناسه، منطقه و MAC خوانده‌شده دوباره پیش از فلش کنترل می‌شوند.
۵. موفقیت فقط وقتی اعلام می‌شود که esptool خروجی تأیید هش را برگرداند. بعد از فلش موفق، گیتوی در دفتر برنامه ثبت می‌شود.

فلش خالی/بدون تنظیمات عمداً حذف شده است؛ هر برد باید شناسه و منطقهٔ مشخص داشته باشد. صفحهٔ پورتال Wi-Fi نیز از فریمور فعال حذف شده است.

## پورت و ابزارها

موتور `src/provisioner.py` ابزارهای بسته‌شده را اولویت می‌دهد؛ روی ویندوز مقصد نیازی به نصب Arduino یا Python نیست. برد فقط برای برنامه‌ریزی به USB وصل می‌شود. کابل شبکهٔ W5500 برای DHCP و MQTT لازم است و باید به شبکهٔ اختصاصی/روتر دارای DHCP وصل شود؛ اتصال مستقیم به لپ‌تاپ به‌تنهایی DHCP فراهم نمی‌کند.

روی لینوکس در صورت خطای دسترسی پورت، گروه `dialout` را بررسی کنید. در ویندوز برای CP210x ممکن است درایور لازم باشد. اگر برد وارد حالت دانلود نشد، BOOT را نگه دارید، EN را یک‌بار بزنید، سپس BOOT را رها کنید.

## آزمون‌ها

```bash
uv run python tests/test_provisioner.py
uv run python tests/test_provisioning_ui.py
```

این آزمون‌ها اعتبارسنجی برد، ساخت فایل تنظیمات LittleFS، رد بستهٔ قدیمی، مسیرهای UI و ثبت گیتوی را بررسی می‌کنند. DHCP و ارتباط واقعی با بروکر هنوز با سوئیچ/شبکهٔ نهایی HSE آزمایش نشده‌اند.
