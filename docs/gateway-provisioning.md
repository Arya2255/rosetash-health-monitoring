# آماده‌سازی گیتوی از داخل برنامه (فلش بدون زنجیرهٔ ساخت)

> صفحهٔ «آماده‌سازی گیتوی» در برنامه — برد نو را با کابل وصل می‌کنی، چند کلیک، گیتوی آنلاین می‌شود.
> وضعیت: 🟢 زنجیرهٔ کامل روی لینوکس با فلش واقعی تأیید شد (۲۰۲۶-۱۰-۱۱) — فریمور `0.2.1-setup` · پورتال راه‌اندازی روی برد واقعی پخش می‌شود · هنوز مانده: تست روی سیستم ویندوز مقصد + ست‌کردن از مرورگر گوشی در کارخانه (تست فیزیکی خود کاربر)
> مستندات مکمل: `docs/gateway-setup.md` — راه‌اندازی توسعهٔ فریمور (arduino-cli) · `docs/live-pipeline.md` — پل زنده · `firmware/gateway/README.md` — نمای فریمور

## 🎯 چرا؟

فلش فریمور قبلاً فقط از لپ‌تاپ لینوکسی با arduino-cli ممکن بود. اپ در نهایت روی سیستم‌های **ویندوزی** نصب می‌شود و اصلاً نباید نیازی به نصب پایتون/آردوینو روی آن باشد. راه‌حل: فایل‌های آمادهٔ فریمور + ابزارهای فلش، از قبل بسته‌بندی می‌شوند و همان برنامه خودش برد را کامل فلش می‌کند.

## 📦 بستهٔ همراه برنامه

مسیر: `distribution/gateway-provisioner/`

```
firmware/            تصاویر آمادهٔ فلش (باینری ثابت، نه سورس)
  bootloader.bin       0x1000
  partitions.bin       0x8000
  boot_app0.bin        0xe000
  app.bin              0x10000   (فریمور کامل گیتوی)
  littlefs-blank.bin   0x3D0000  (تصویر خالی — برد با این، AP راه‌اندازی باز می‌کند)
tools/
  windows-amd64/       esptool.exe + mklittlefs.exe + dll + لایسنس‌ها
  linux-x86_64/        mklittlefs (برای ساخت ایمج کانفیگ در لحظه)
manifest.json          آدرس‌ها، باود، حالت فلش + sha256 هر فایل
```

ساخت/تازه‌سازی بسته:

```
python3 tools/build_provisioner_bundle.py                # کامپایل + کپی + هش
python3 tools/build_provisioner_bundle.py --no-compile   # فقط بازسازی manifest/هش
python3 tools/build_provisioner_bundle.py --fetch-tools  # دانلود ابزارهای ویندوز
```

نکتهٔ مهم: باینری‌ها از خروجی **همان کامپایل تازه** کپی می‌شوند — هیچ‌وقت باینری کهنه دستی کنار گذاشته نشود (پیت‌فال ثبت‌شده: یک‌بار باینری قدیمی فلش شد).

## 🖥️ صفحهٔ «آماده‌سازی گیتوی» در برنامه

سه گام در یک صفحه:

1. **برد** — «اسکن پورت‌های سریال» → انتخاب پورت → «خواندن مشخصات برد» (چیپ/فلش/MAC از خود برد). اگر مک برد با مک ثبت‌شدهٔ گیت‌وی انتخاب‌شده نخواند یا برد قبلاً برای گیت‌وی دیگری ثبت شده باشد، هشدار صریح می‌آید.
2. **مشخصات** — شناسهٔ گیت‌وی (تراشه‌های دفتر برای انتخاب سریع)، نام نمایشی، منطقه، وای‌فای و آدرس بروکر. وای‌فای/آدرس از پل (`GET /api/netinfo`) پیش‌پر می‌شود — ssid و رمز همان سیستمی که برنامه رویش اجراست، و پیشنهاد بروکر بر اساس ساب‌نت گیت‌وی‌های زنده.
3. **فلش** — دو حالت:
   - **با کانفیگ همین حالا** (پیشنهادی): `config.json` ساخته می‌شود، تصویر LittleFS در لحظه با mklittlefs ساخته و همهٔ پنج فایل نوشته می‌شود؛ بعد از موفقیت گیت‌وی خودکار در دفتر پل ثبت می‌شود.
   - **بدون تنظیمات**: پنجرهٔ [بدون تنظیمات] — برد بعد از نصب خودش AP راه‌اندازی باز می‌کند و از گوشی نصب‌کار ست می‌شود.

پیشرفت زندهٔ esptool (درصد + لاگ) در همان کارت دیده می‌شود و در پایان وضعیت verify («هش همهٔ فایل‌ها تأیید شد») می‌آید. فلش در نخ جداگانه اجرا می‌شود — پنجره قفل نمی‌شود.

موتور این صفحه `src/provisioner.py` است (فقط کتابخانهٔ استاندارد) و بیرون از برنامه هم قابل استفاده است:

```
from provisioner import find_tools, list_serial_ports, read_chip_info
from provisioner import build_config, build_littlefs, flash_gateway
```

انتخاب ابزار به‌ترتیب اولویت: متغیر محیطی (`ROZTASH_ESPTOOL`) → بستهٔ همراه → نصب آردوینو → PATH. روی سیستم ویندوز مقصد، همان `tools/windows-amd64/` جواب می‌دهد و هیچ چیز اضافه‌ای لازم نیست.

## 📡 مسیر بدون کابل — پورتال راه‌اندازی برد

برد بدون کانفیگ معتبر (فایل نبود / وای‌فای وصل نشد)، خودش می‌رود در حالت راه‌اندازی:

- شبکهٔ Wi-Fi باز با نام `RoztashGw-XXXXXX` (سه بایت آخر مک برد) پخش می‌شود
- از مرورگر گوشی: `http://192.168.4.1/` — فرم فارسی؛ اسکن شبکه‌های ۲.۴ گیگاهرتز (`/scan`)، ذخیره و ری‌استارت (`/save`)
- اگر رمز اشتباه باشد یا شبکه پیدا نشود، برد برمی‌گردد به همین فرم — با گوشی درستش کن
- گیت‌وی فقط ۲.۴ گیگاهرتز را می‌بیند؛ شبکه‌های ۵ گیگاهرتز در اسکن نیستند

پورتال فقط برای کانفیگ است (فریمور باید یک‌بار با کابل نوشته شده باشد) و به‌محض اتصال موفق، خودش را می‌بندد و به کار عادی برمی‌گردد.

## 🧪 مسیر تأییدشدهٔ فلش (مرجع دستی)

باود ۴۶۰۸۰۰ (۹۲۱۶۰۰ روی این برد استاب فلشر را می‌شکند)، حالت dio و فرکانس 80m:

```
esptool --chip esp32 --port /dev/ttyUSB0 --baud 460800 write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 4MB \
  0x1000  firmware/bootloader.bin \
  0x8000  firmware/partitions.bin \
  0xe000  firmware/boot_app0.bin \
  0x10000 firmware/app.bin \
  0x3D0000 littlefs.bin
```

- `littlefs.bin` = تصویر خالی بسته، یا تصویر ساخته‌شده از `config.json` (با mklittlefs، سایز `0x20000`)
- فلش تازهٔ فریمور بدون دست‌زدن به تنظیمات، فقط `0x10000 app.bin` است
- esptool خودش پس از نوشتن، هش را verify می‌کند («Hash of data verified») — موفقیت فلش یعنی همین خط، نه فقط کد خروج صفر

## 🛠 عیب‌یابی — چیزهایی که واقعاً پیش آمدند

| نشانه | علت / راه‌حل |
|---|---|
| هیچ پورتی ساخته نمی‌شود | کابل «فقط-شارژ» — کابل دیتادار را عوض کن |
| ویندوز: پورت آمد ولی باز نمی‌شود | درایور CP210x (سیلیکون‌لبز) لازم است |
| لینوکس: `Permission denied` | کاربر باید عضو dialout باشد؛ در سشن موجود `sg dialout -c "…"` |
| «برد جواب نداد» | دکمهٔ BOOT را نگه دار، یک‌بار EN را بزن، دوباره بخوان |
| AP با نام `RoztashGw-000000` | باگ رفع‌شده (خواندن MAC قبل از روشن‌شدن رادیو صفر برمی‌گشت) — از `0.2.1-setup` به بعد `esp_read_mac` از efuse می‌خواند |
| فلش وسط کار قطع می‌شود | کابل/پورت USB را عوض کن؛ روی هاب USB غیرفعال نزن |
| گیت‌وی آفلاین ماندن بعد از فلش | وای‌فای ۲٫۴ و رمز را چک کن؛ برد خودش هر ۱۵ ثانیه دوباره تلاش می‌کند |

پیت‌فال ابزار: esptool خروجی کامپایل پیش‌فرض arduino-cli را در `~/.cache/arduino/sketches/…` می‌نویسد — همیشه از output-dir همان کامپایل فلش کن.
